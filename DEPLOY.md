# Deploying AI Work Flow for free

| Part | Host | Free plan notes |
|---|---|---|
| Website (`frontend/`) | Vercel | Always on |
| Backend (`backend/`) | Render | Sleeps after 15 min idle; first visit after that takes up to a minute |
| AI service (`ai-service/`) | Render (Docker) | Same sleep; its disk is wiped on every restart |
| Database | Neon | Always on, does not expire |

Render's free plan gives 750 hours a month per account, which covers both
services because they sleep when nobody uses them.

**Before you start**, sign up at vercel.com, render.com and neon.tech using
"Sign up with GitHub", and have your Gemini API key ready
(aistudio.google.com/apikey). Never paste keys or passwords into a file in this
repository; they only go into each host's settings.

## 1. Database (Neon)

1. Create a project (any name, closest region).
2. On the dashboard, click **Connect**, turn **Connection pooling off**, and copy
   the connection string. It looks like
   `postgresql://user:password@ep-xxxx.region.aws.neon.tech/neondb?sslmode=require`.
   The backend runs database migrations on start, which need this direct
   (non-pooled) address.

## 2. Backend and AI service (Render)

1. **New → Blueprint**, pick this repository. Render reads `render.yaml` and
   shows two services: `ai-workflow-backend` and `ai-workflow-ai-service`.
2. Fill in the values it asks for:

   | Setting | Service | Value |
   |---|---|---|
   | `DATABASE_URL` | both | the Neon string from step 1 (the same string in both) |
   | `SEED_ADMIN_PASSWORD` | backend | a password you choose for `admin@aiworkflow.dev` |
   | `SEED_CLIENT_PASSWORD` | backend | a password you choose for `client@aiworkflow.dev` |
   | `OPENAI_API_KEY` | AI service | your Gemini key |
   | `AI_SERVICE_URL` | backend | `https://ai-workflow-ai-service.onrender.com` |
   | `BACKEND_URL` | AI service | `https://ai-workflow-backend.onrender.com` |
   | `CORS_ORIGIN` | backend | `https://ai-workflow.vercel.app` for now; you fix it in step 4 |

   `JWT_SECRET` and `INTERNAL_SERVICE_SECRET` are generated by Render; leave them.
3. Click **Apply**. The first build takes a few minutes. When both show
   **Live**, open each service and check its real address at the top of the page.
   If Render added a suffix (for example `ai-workflow-backend-x1y2.onrender.com`),
   update `AI_SERVICE_URL` and `BACKEND_URL` to the real addresses.
4. Check them: `https://<backend>.onrender.com/health` should show
   `"db":"up"`, and `https://<ai-service>.onrender.com/health` should show
   `"mock_mode":false`.

## 3. Website (Vercel)

1. **Add New → Project**, import this repository.
2. **Root Directory**: `frontend`. Vercel detects Vite by itself.
3. **Environment Variables**: `VITE_API_URL` = your backend address,
   for example `https://ai-workflow-backend.onrender.com` (no trailing slash).
4. **Deploy**, then copy the site address (for example `https://ai-workflow-abc.vercel.app`).

## 4. Connect the website to the backend

On Render, open `ai-workflow-backend` → **Environment**, set `CORS_ORIGIN` to
the Vercel address from step 3 (no trailing slash), and save. Render redeploys.
To also allow your local dev server, separate addresses with a comma:
`https://ai-workflow-abc.vercel.app,http://localhost:5173`.

## 5. Try it

Open the Vercel site. If it was idle, the first sign-in can take up to a minute
while Render wakes the backend. Sign in as `admin@aiworkflow.dev` or
`client@aiworkflow.dev` with the passwords you chose in step 2.

## What behaves differently online

- **Preview links** for generated projects point to
  `https://<ai-service>/preview/<project-id>/` instead of `localhost:7100`.
- **Previews restart themselves.** Render wipes the AI service's disk when it
  restarts or wakes from sleep. Each project's generated code is saved in the
  database when it deploys, so the first visit to a preview after a restart
  restores the code and starts the app (a few extra seconds). At most 3 previews
  run at once on the free plan's 512 MB; the least recently used one stops and
  starts again on its next visit (`MAX_RUNNING_PREVIEWS` changes the cap).
- **Gemini's free tier** has per-minute limits; a large project can briefly hit them.

## Updating

Push to `main` on GitHub. Render and Vercel rebuild automatically.
